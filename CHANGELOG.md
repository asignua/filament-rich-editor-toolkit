# Changelog

All notable changes to `asignua/filament-rich-editor-toolkit` are documented here.

## v1.1.1 - 2026-10-25

### Fixed

- **Strict paste with Filament 5.10.** Filament 5.10 renders tool buttons as `mountToolAction('name', ...)` instead of `$wire.mountAction('name', ...)`. `paste-strict.js` only recognised the old call, so a field offering only the toolkit's "Link options" / "Image properties" button (which borrow the active state of `link` / `image`) was read as having a Link / Image button, and paste kept links and images it should have stripped. Both spellings are recognised now. Run `php artisan filament:assets` (`paste-clean.js` changed).
- Tests asserting the toolbar markup accept both spellings.

## v1.1.0 - 2026-10-12

### Upgrade notes (from 1.0.x)

- **Rendering changes without any code change.** `RichEditorToolkit::plugins()` / `renderer()` now include `LinkOptionsPlugin` and `ImagePropertiesPlugin`: (1) `<a>`: `target` is `_blank` or dropped, `rel` is filtered to `link_options.rel_tokens`, `_blank` forces `noopener noreferrer`; (2) an old `<figure><img><figcaption>` is read as an image with a caption and re-rendered as `<span class="asignua-rte-figure">…<span class="asignua-rte-caption">`, markup inside the figcaption is flattened; (3) `<img alt="">` is kept (it used to be dropped). They stay on by default, because the editor-side plugins need them at render time (a saved caption would otherwise vanish from the page). To keep the 1.0 output: `RichEditorToolkit::renderer($html, links: false, images: false)`, `RichEditorToolkit::plugins(links: false, images: false)` or the config `renderer.link_options` / `renderer.image_properties` set to `false`.
- **Google Docs picture download** (`uploadImages()`, off by default): needs a logged-in user now (set `paste_clean.remote_image_guests` or `authorizeRemoteImages()` to allow guests), goes out without a proxy, and is never decompressed. A wildcard allow-list entry over a public suffix (`*.co.uk`) no longer matches.
- Run `php artisan filament:assets`: new and changed modules.

### Browser check fixes (v1.1 to v1.4)

- `ImagePropertiesPlugin`: the browser module ships its `image` shadow inside a wrapper extension. Filament 5.9 replaces a built-in extension that a custom module returns under the same name, which dropped Filament's own image node: inserted and loaded images lost `src`, `alt`, `data-id`, the size and the resizable view.
- `ImageProperties` (PHP) renders THROUGH the image node the application bound for Filament's `ImageExtension` (`app(ImageExtension::class)`) instead of the stock class: a media manager or a site that rebinds the node (resolving `src` from `data-id`, lazy loading, a library alt) is no longer shadowed. A decorative image still gets `alt=""` even when that node fills in a default.
- `PasteCleanPlugin`: a heading that is the text of a list item becomes the item's paragraph. Google Docs writes `<li><h3 role="presentation">` for a list whose paragraphs use a heading style; the editor then wrapped each item's text in a generic `<div>` around a heading that was no heading at all.
- `PasteCleanPlugin`: the underline Google Docs and Word put on every link is not kept as `<u>` inside the link (a link is underlined anyway, and the `<u>` stayed underlined where a site's CSS removes it); an underline outside links is kept.
- The "Image properties" dialog no longer marks Alignment as required ("Default" is a valid choice).
- The caption and the alignment are visible in the editor on resizable images too (Filament's node view sets an inline `display: inline-flex`).
- `FullscreenPlugin`: Esc typed inside the editor leaves fullscreen (ProseMirror calls `preventDefault()` on every Esc in a focused editor); an Esc that closes a mention or merge-tag list still does not; the toolbar button is no longer shown as pressed after leaving with Esc.
- `FullscreenPlugin` and `SourceCodePlugin` re-apply their state after Livewire morphs the field (saving, a refresh, a file upload): before, the page stayed scroll-locked while the editor dropped back into the form, or the editor and the source box were shown at the same time.

### Review fixes (v1.1 to v1.4)

- `RemoteImageFetcher`: the request ignores `HTTPS_PROXY`/`ALL_PROXY` (with a proxy the DNS pin only fixed the address of the proxy, which resolved the name itself); the response is not decompressed and is written to a capped sink, so a gzip bomb cannot get past the byte cap; a transfer that crosses the cap is aborted at once, by a SHORT write (`fwrite()` returns 0, from a stream wrapper), which libcurl turns into an abort on Guzzle 7 as well as 8 (a failing write would throw in Guzzle 7's write callback, which curl ignores: the download ran to the timeout; measured against an endless chunked body with a 100 KB cap: 15 s before, 0.2 s after); IPv4-translated `::ffff:0:a.b.c.d`, `3fff::/20` and `5f00::/16` are not public. (`CURLOPT_MAXFILESIZE_LARGE` is not used: Guzzle 8 rejects it.)
- `PasteCleanPlugin`: the fetch action is authorised (logged-in user by default, `authorizeRemoteImages()`), with a per-field rate-limit bucket besides the per-viewer one; wildcard hosts over public suffixes match nothing, in PHP and in the browser (shared fixture `tests/fixtures/host-allow.json`).
- Pasted pictures: the re-dispatched paste answers `getData('text')`/`getData('url')` like a real clipboard and carries no files (Word for Mac's PNG of the text was uploaded as well); pictures that Filament just uploaded survive when their temporary URL is on another host (S3, a different `app.url`), identified by a one-time token, never by a forgeable `data-id`; the form is always released when the editor is destroyed during the download.
- Paste inside the editor keeps the caption and alignment of an image (Filament's paste handler split the wrapper and left the caption as loose text).
- Strict paste: the toolkit's own "Link options" / "Image properties" buttons no longer count as a Link button / an image tool; any other tool that mounts its own dialog counts as what it names, so a field with `asignua/filament-rich-links` instead of the stock Link button keeps its links.
- Source view: a change that comes from outside (the server rewriting attachment ids on save) rebuilds the textarea instead of being overwritten by it later; Ctrl/Cmd+S (and any Ctrl/Cmd chord) flushes at once. (No Livewire `commit` hook: Livewire builds the request's updates before that hook and Filament copies the editor state on the next tick, so it would be too late.) Text typed but not yet pushed when such a change arrives is kept in the box with a status message (new string `source_code_conflict`, all 10 languages) and is not pushed (it carries stale attachment ids); leaving source mode discards it.
- `Support\PlainText` (the `RichTextLength` rule) skips only the caption of a real image wrapper (the same test as `ImageProperties::adopt()`), matching the browser counter; a `<p class="asignua-rte-caption">` or a `<figcaption>` elsewhere is counted (fixture cases added).
- `PasteCleanPlugin`: both rate-limit buckets are checked before either is hit, so a refused request no longer burns the other bucket.
- `remote_image_hosts`: internationalised names must be written in punycode (documented); the public-suffix list gained `kyiv.ua` and shared-hosting domains (`github.io`, `amazonaws.com`, `cloudfront.net`, `pages.dev`, `netlify.app`, `vercel.app`, `herokuapp.com`, `azurewebsites.net`, `blogspot.com`, `appspot.com`, `firebaseapp.com`, `web.app`, `workers.dev`).
- `LinkOptionsPlugin`: the existing `rel` that the browser sends back with the dialog is filtered through `link_options.rel_tokens`, and `opener` is never stored.
- Fullscreen: Esc that leaves fullscreen no longer also closes a modal the editor sits in.

- `LinkOptionsPlugin` (`linkOptions` toolbar button, enabled inside a link): a dialog for "Open in a new tab" and the rel tokens `nofollow`, `sponsored`, `ugc`, written with `updateAttributes('link', …)` on the link under the cursor (a bare cursor first selects the mark's range). A second button on purpose: Filament's `LinkAction` is a static factory without a seam, and `asignua/filament-rich-links` writes into the same mark. A new tab stores `rel="noopener noreferrer"`; tokens the dialog does not manage are kept. Server half (added to `RichEditorToolkit::plugins()` / `renderer()`): `Support\LinkAttributes` normalises every `<a>` of the output after the sanitizer: `target` is `_blank` or dropped, `rel` is filtered to `link_options.rel_tokens` (the HTML link types without `opener`), `_blank` forces `noopener noreferrer`, and `link_options.external_rel` / `LinkOptionsPlugin::externalRel()` adds tokens to absolute links that leave the site (`app.url` host and `internal_hosts` are the site; render time only). `rel` and `target` are allowed on `<a>` in the toolkit's sanitizer even when the host's config is stricter. No browser module: the TipTap mark already carries both attributes. Filament issues #16829, #19478, discussions #5705, #19028. **Behaviour change** for users of `RichEditorToolkit::plugins()` / `renderer()`: stored `rel` values outside the whitelist and `target` other than `_blank` are no longer rendered.
- `PasteCleanPlugin::uploadImages()` / `paste_clean.upload_images` (off by default): pictures pasted from Word and Google Docs are uploaded instead of removed. A new module, `paste-images.js` (priority 1000, before Filament's `localFiles`), rewrites the clipboard before Filament's paste handler reads it and re-dispatches the paste, so Filament's own pasted-`data:`-image upload does validation (accepted types, max size), storage and the `data-id`; nothing is stored as base64. Word: the bytes come from `text/rtf` (a pure extractor: `\pict` groups, `\pngblip`/`\jpegblip` hex, `\shppict` used, `\nonshppict`/`\shprslt`/list pictures skipped, EMF/WMF/`\bin` unusable) and are matched to the `file:///` `<img>`s by order; a count mismatch matches nothing. Google Docs: the browser mounts the modal-less editor action `asignuaFetchRemoteImage` (the return value of a modal-less action reaches the browser) and gets a `data:` URL. Pictures that cannot be recovered are removed and counted ("Images that could not be imported: :count", shown with Filament's file-validation message). Runs only on fields with file attachments.
- `Support\RemoteImageFetcher`, the SSRF guard behind it: https/443 only, no credentials or URL oddities, host allow-list `paste_clean.remote_image_hosts` (default `*.googleusercontent.com`; a wildcard over a public suffix such as `*.co.uk` / `*.com.ua` matches nothing), DNS resolved server-side with every address required to be public (loopback, private, link-local, CGNAT, documentation, multicast, `3fff::/20`, `5f00::/16` and the IPv6 ranges that wrap an IPv4 address: mapped `::ffff:a.b.c.d`, translated `::ffff:0:a.b.c.d`, NAT64, 6to4, Teredo), connection pinned to the checked address, **no proxy** (whatever `HTTPS_PROXY`/`ALL_PROXY` say), no redirects, timeouts, a byte cap on the bytes off the wire (`Content-Length` plus a capped sink that aborts the transfer; the response is never decompressed and a `Content-Encoding` answer is refused), type decided by magic bytes (png/jpeg/gif/webp). The action also requires an enabled field with attachments and a logged-in user (`paste_clean.remote_image_guests`, `PasteCleanPlugin::authorizeRemoteImages()`), and is rate limited per viewer and per viewer+field (`paste_clean.remote_image_rate_limit`, `remote_image_rate_limit_per_field`); it returns only `data:` URLs and error codes.
- Config: `paste_clean.upload_images`, `remote_image_hosts`, `remote_image_max_kb`, `remote_image_rate_limit`, `remote_image_rate_limit_per_field`, `remote_image_guests`; `renderer.link_options`, `renderer.image_properties`; `link_options.rel_tokens`, `external_rel`, `internal_hosts`.
- Translations (all 10 languages): `paste_images_failed`, `paste_images_fetch`, `link_options`, `link_options_new_tab`, `link_options_new_tab_hint`, `link_options_rel`, `link_options_rel_hint`, `rel_nofollow`, `rel_nofollow_hint`, `rel_sponsored`, `rel_sponsored_hint`, `rel_ugc`, `rel_ugc_hint`. Run `php artisan filament:assets` after upgrading (a new module, `paste-images.js`).
- `ImagePropertiesPlugin`: an `imageProperties` toolbar button (enabled while an image is selected, optionally also in the image's floating toolbar) opening a dialog with alternative text, a "decorative image" switch, a plain-text caption and left/center/right alignment. The stock "Attach files" dialog already edits alt text; this adds what it cannot: an explicit empty `alt=""` (the stock dialog turns an empty field into a missing alt, and the server-side node drops an empty one), a caption and alignment. It extends the existing `image` node (a lower-priority shadow in TipTap, a higher-priority subclass of Filament's `ImageExtension` in tiptap-php), so `data-id`, resizable images, `ImageUrlPlugin`, `CustomAttributesPlugin` and the source view keep working. An image without caption and alignment is the stock `<img>` unchanged; with either it is `<span class="asignua-rte-figure asignua-rte-align-*"><img><span class="asignua-rte-caption">`, not `<figure>` (Filament's image is inline, a `<figure>` inside the `<p>` would be invalid). A `<figure>`/`<figcaption>` typed in the source view or pasted is read and rewritten. Captions are escaped, the alignment is a whitelist. Added to `RichEditorToolkit::plugins()` / `renderer()`. An optional front-end stylesheet is publishable with `--tag=filament-rich-editor-toolkit-front-css`. Filament discussions #8455, #20296, issue #16860.
- Source view: a typed `<figure>` that the editor rewrites to the image wrapper no longer raises the "unsupported markup" notice; dropped wrapper attributes and markup in a caption still do.
- `PasteCleanPlugin`: "Clear formatting" keeps the image wrapper; a paste drops the caption of a pasted captioned image instead of leaving it as loose text.
- Translations (all 10 languages): `image_properties`, `image_properties_alt`, `image_properties_alt_hint`, `image_properties_decorative`, `image_properties_decorative_hint`, `image_properties_caption`, `image_properties_caption_hint`, `image_properties_align`, `align_none`, `align_left`, `align_center`, `align_right`, `apply`.
- `SourceCodePlugin`: a `sourceCode` toolbar button that swaps the editor for a textarea with the pretty-printed HTML (`<pre>` untouched, void elements without a closing tag; `->indent()` / `source_code.indent`) and back. The edit returns only through the editor's schema (`setContent(html, { emitUpdate: true })`, a detached `DOMParser`, never a live element), so the field state follows Filament's own `update` handler. After a round trip that dropped or changed something material (unknown elements, lost attributes, text, heading level, list type; whitespace, attribute order, `<b>`/`<strong>` and attributes the editor added are ignored) a non-blocking status notice says "Some markup is not supported by this editor and was removed." The textarea is synced 400 ms after typing, on blur/change, on the form's `submit` and on leaving, so saving while in source mode keeps the source; other toolbar tools are disabled meanwhile; `aria-pressed` toggle, labelled textarea, Tab is not trapped, dark mode, fills the screen in fullscreen. Filament discussions #17718, #19141.
- `FullscreenPlugin`: a `fullscreen` toolbar button that turns the field into a full-viewport overlay and back. Esc leaves, the page scroll is locked and restored, the toolbar stays on top, `aria-pressed` follows the state. A fixed overlay at `z-index: 35` (above the topbar and sidebar, below Filament's modals so toolbar dialogs stay on top), configurable with `zIndex()`, `fullscreen.z_index` or `--asignua-rte-fullscreen-z`. Works in sections, tabs, repeaters, modals and plain Livewire forms.
- `CharacterCountPlugin`: a counter under the editor ("Characters: 123 / 500 · Words: 20 / 80") on the plain text, amber from `warnAt()` (`character_count.warn_at`, default 90%), red over the limit, with a one-time screen reader announcement when the limit is exceeded.
- `Rules\RichTextLength` (min/max characters, max words) and the `RichEditor::textLength(max:, maxWords:, min:, counter:, showWords:)` macro that adds the rule and the counter. Both count the same plain text (`Support\PlainText` in PHP, `character-count.js` in the browser), from an HTML string or TipTap JSON, pinned by shared fixtures on both sides. Translatable messages.
- `PasteCleanPlugin::strict()` / `paste_clean.strict` (off by default): a paste is reduced to what the field's toolbar offers (no table button: tables become paragraphs; no heading button: paragraphs, a missing level moves to the nearest offered one; no list button: paragraphs; marks without a button are unwrapped). The module reads the rendered toolbar, so no macro or extra configuration is needed. Applies to a paste from inside an editor too. Filament discussions #20484, #20048.
- A new stylesheet, `filament-rich-editor-toolkit-ui.css`, loaded on request by the fullscreen and counter modules (no `StickyToolbarPlugin` needed). Run `php artisan filament:assets` after upgrading.
- Translations (all 10 languages): `fullscreen`, `characters_count`, `characters_count_max`, `words_count`, `words_count_max`, `characters_over`, `words_over`, `text_length_max`, `text_length_min`, `text_length_max_words`, `source_code`, `source_code_label`, `source_code_unsupported`.

## v1.0.2 - 2026-10-08

- Dependencies: jsdom 30, esbuild 0.28 (dev); the built assets are unchanged.
- Clean format: a selection that spans a custom block is also put back as an open slice, so its first and last paragraphs are no longer split. The open ends are clamped to the depth of the cleaned first/last node (a custom block is closed; a flattened wrapper such as a `<div>` no longer leaves an end deeper than the node), and this is covered by tests on a real `prosemirror-model` schema (`prosemirror-model` is now a dev dependency).
- `EmbedPlugin` (security): the editor no longer draws an `<iframe>` it did not vet. A node built from JSON (`RichEditor::json()` stores a posted document as is) with a `javascript:` or foreign `src` is replaced by an inert placeholder in the panel, and the configured `sandbox`, `allow` and `referrerpolicy` are forced in the editor as they are on render; before, such a node ran in the panel's origin for every admin who opened the record.
- `EmbedPlugin`: YouTube's own embed code (`www.youtube.com/embed/ID`), `watch?v=`, `youtu.be` and `vimeo.com/ID` iframes from the source view, a paste or migrated content are rebuilt to the built-in `youtube-nocookie.com` / `player.vimeo.com` form instead of being dropped (`EmbedIframe::canonicalSrc()`, mirrored in the browser). A playlist (`embed/videoseries`) or channel (`embed/live_stream`) URL is no longer taken for a video id.
- `CustomAttributesPlugin`: a `<div>` that wraps an `<iframe>` (the responsive embed wrapper) is a block container, so the iframe stays inside it instead of being lifted out and leaving an empty div.
- `CustomAttributesPlugin`: the classes and declarations another extension writes itself are dropped only on the tag it writes them on (`text-align` on `p`/`h1`-`h6`, `width`/`height` on `img`, `--color` on `span`, `--cols`/`grid-layout`/`lead` on `div`). A hand-written `text-align` or `width` on a `td`, `table`, `div` or `iframe`, and Bootstrap's `<p class="lead">`, are kept; before they were lost silently.
- `CustomAttributesPlugin`: the span mark no longer captures Filament's mention and merge-tag spans (`data-type`) when HTML is parsed in the browser; a copied merge tag came back as plain text with its `data-id` lost.
- `PasteCleanPlugin`: "Clear formatting" puts the result back as an open slice like a paste, so a few words picked out of a paragraph stay in it instead of splitting it into three; with a table cell selection it does nothing instead of wrecking the table.
- `PasteCleanPlugin`: "Clear formatting" keeps what the editor produced: mentions and merge tags, grid and columns, details, the lead paragraph, and a link's `target="_blank"` / `rel`.
- `PasteCleanPlugin`: a space inside a link `href` becomes `%20` instead of being removed (`Shared Documents/Plan 2026.docx` no longer turns into a different address); the script-scheme check still ignores spaces and control characters.
- `ImageUrlPlugin`: a valid address on a host outside `hosts()` gets its own message (`image_url_host_not_allowed`, all 10 locales) instead of "Enter a full http(s) address"; the button uses a photo icon, not the chain icon of the stock Link button.
- `StickyToolbarPlugin`: a per-field `RichEditor::stickyOffset()` wins over the plugin offset, and the plugin offset no longer applies inside a modal, where Filament's measured header height is used (the plugin offset stays ahead of Filament's default, so `offset()` works outside modals).

## v1.0.1 - 2026-10-05

- `PasteCleanPlugin`: the "Clear formatting" button no longer destroys nodes the editor itself produced. Embeds (`<iframe>` from `EmbedPlugin`), images (also `ImageUrlPlugin` images and images on another host) and code blocks in the selection are kept as they are; before, the iframe was dropped, the image removed by the clipboard image triage and a code block flattened into one paragraph.
- `PasteCleanPlugin`: the button keeps every link of existing content (relative paths, `#anchors`, `tel:`) and refuses only `javascript:`, `vbscript:`, `data:` and `file:`; `keepLinkPrefixes()` is no longer needed for relative sentinels. A paste now keeps `tel:` links as well; relative and `#` links in a paste are still turned into text.
- `EmbedPlugin`: a `host/path` allow-list entry keeps the case of its path (only the host is lowercased), so an entry with capitals in the path, such as a Google Forms id, matches again; before, it never matched and the embed was refused.
- Docs: a name a node declares itself wins over `CustomAttributesPlugin`'s, so `id` on an `<img>` (Filament's image node owns it as the media key) is not kept; `class`/`style` are. A test pins it.

## v1.0.0 - 2026-10-03

- `PasteCleanPlugin`: cleans a paste from Word / Google Docs (structure kept; colours, fonts, backgrounds, class/id/style dropped) and a "Clear formatting" toolbar button that keeps headings, lists, links and custom blocks. Configurable list of link prefixes the button must keep.
- `CustomAttributesPlugin`: preserves `class`, `id`, `style` and an explicit allow-list of further attributes (`data-*`, `aria-*`, ...) in the browser schema and in the tiptap-php schema; keeps generic `<div>` containers, bare `<span>` and `<li><div>` structures.
- `EmbedPlugin`: `<iframe>` node and an "Embed" button for YouTube, Vimeo and allow-listed https hosts; embeds are rebuilt from provider and id, forced to carry `sandbox`, `allow`, `referrerpolicy` and `loading="lazy"`.
- `ImageUrlPlugin`: "Image by URL" button, optional host restriction.
- `StickyToolbarPlugin`: panel plugin (CSS only) that keeps the toolbar visible on long content and un-breaks `position: sticky` inside clipping sections, tabs and repeaters.
- `RichEditorToolkit::renderer()` / `plugins()` / `toHtml()` / `sanitizer()` for the front end: attributes and embeds survive rendering through the toolkit's own sanitizer.
- Security hardening before the first release:
  - Filament's shared HTML sanitizer is no longer extended. The toolkit renders through its own sanitizer (a copy of Filament's config), so `TextColumn::html()`, `TextEntry::html()`, notifications and the Markdown editor never let `<iframe>` or the extra attributes through. A renderer you build yourself must be rendered with `RichEditorToolkit::toHtml($renderer)`; `RichEditorToolkit::allowEmbeds()` is a deprecated no-op.
  - The iframe `src` allow-list is checked when a node is rendered too (JSON content never passes through `parseHTML()`), and once more by the toolkit's sanitizer.
  - Embed path prefixes match on a segment boundary; paths with dot segments, `%2e`, `%2f` or backslashes are refused (PHP and JS agree, scheme is case-insensitive on both sides).
  - Attribute names: framework directives (`x-*`, `hx-*`, `v-*`, `ng-*`, `wire:*`), names with `:`, `is`, `srcset`, `ping`, `poster`, `background`, `formtarget`, `xmlns*` and similar are never accepted.
  - `CustomAttributesPlugin::attributes()` no longer registers its names globally; pass the same list to `RichEditorToolkit::renderer($html, attributes: [...], types: [...])`.
- Unlisted Vimeo videos keep their privacy hash (`?h=`).
- Sticky toolbar follows the panel's colour variables and leaves containers whose editors all opted out alone.
- Compiled ES modules in `resources/dist`, registered with `FilamentAsset` and loaded on request; node unit tests for the JS.
- Translations: English, Ukrainian, German, Spanish, French, Italian, Dutch, Polish, Brazilian Portuguese and Turkish.
- Laravel Boost guidelines.
